# Cloud-1 Roadmap

> How this project automates Inception deployment with Ansible.

---

## Subject Requirements Compliance

| Requirement | Implementation |
|-------------|---------------|
| Fully automated deployment | `./deploy.sh deploy` runs Ansible end-to-end |
| Auto-restart on reboot | `restart: unless-stopped` on all containers |
| Data persistence | Bind-mount volumes at `/opt/cloudone/data/{db,wp}` |
| Multi-server parallel deploy | `inventory/hosts.yml` supports multiple hosts, playbooks target `hosts: all` |
| Ubuntu 20.04 LTS target | Only assumes SSH + Python on target |
| 1 process = 1 container | MariaDB, WordPress (php-fpm), Nginx, Redis, phpMyAdmin each in own container |
| Public access limited | UFW denies all except 22/80/443; DB/Redis internal only; phpMyAdmin via SSH tunnel |
| docker-compose.yml | `roles/cloudone/files/docker/docker-compose.yml` |
| SQL works with WP + phpMyAdmin | MariaDB shared on `cloudone` network, phpMyAdmin configured to connect to `mariadb` host |
| TLS | Self-signed cert generated by Nginx entrypoint; HTTP→HTTPS redirect |
| URL-based routing | Nginx reverse-proxies `*.php` to WordPress php-fpm |
| No secrets in repo | All credentials via environment variables, templated into `.env` and secret files on server |

## Ansible Architecture

### Inventory

```
inventory/
├── hosts.yml           # Target hosts (uses SERVER_IP env var)
└── group_vars/
    └── all.yml         # All shared variables (domain, ports, paths, passwords)
```

- Passwords read from env vars via `lookup('env', ...)` — never hardcoded
- To add servers: duplicate the `cloud1` host entry in `hosts.yml`

### Playbooks

| Playbook | Roles | Use case |
|----------|-------|----------|
| `site.yml` | common → docker → firewall → cloudone | Full deploy from scratch |
| `setup.yml` | common → docker → firewall | Prepare server only |
| `deploy.yml` | cloudone | Redeploy app (server already set up) |
| `destroy.yml` | (inline tasks) | Tear everything down |

All playbooks validate required env vars in `pre_tasks` before running.

### Roles

#### `common`
- Installs base packages (curl, git, python3-pip, etc.)
- Installs Python `docker` module (needed by `community.docker`)
- Creates app directories (`/opt/cloudone`, `/opt/cloudone/data/{db,wp}`)

#### `docker`
- Adds Docker official APT repo + GPG key
- Installs `docker-ce`, `docker-compose-plugin`, `containerd.io`
- Enables + starts Docker systemd service
- Configures daemon (log rotation, overlay2 driver)

#### `firewall`
- Installs UFW
- Default deny incoming, allow outgoing
- Opens only ports 22, 80, 443

#### `cloudone`
1. Stops any existing containers
2. Copies `files/docker/` tree to `/opt/cloudone/` on the server
3. Creates secret files from env vars (`secrets/{db_root_pwd,db_user_pwd,wp_admin_pwd,wp_user_pwd}`)
4. Templates `.env` from `env.j2`
5. Runs `docker compose up --build`
6. Waits for MariaDB health check + WordPress HTTP response

## Deployment Flow

```
Local machine                         Remote server (Ubuntu 20.04)
─────────────                         ────────────────────────────
export SERVER_IP=...
export DB_ROOT_PASSWORD=...
./deploy.sh deploy
    │
    ├─ ansible-playbook site.yml ──SSH──► common: apt install, dirs
    │                                     docker: install Docker CE
    │                                     firewall: UFW rules
    │                                     cloudone:
    │                                       ├─ copy docker files
    │                                       ├─ write .env + secrets
    │                                       ├─ docker compose up --build
    │                                       └─ wait for healthy services
    │
    └─ ✓ Done                         WordPress running on :443
```

## Accessing Services

| Service | How to access |
|---------|---------------|
| WordPress | `https://<DOMAIN_NAME>` |
| WP Admin | `https://<DOMAIN_NAME>/wp-admin` |
| phpMyAdmin | `ssh -L 8081:localhost:8081 root@<SERVER_IP>` then `http://localhost:8081` |

## Adding a New Server

1. Add a host entry in `inventory/hosts.yml`:
   ```yaml
   cloud2:
     ansible_host: "{{ lookup('env', 'SERVER2_IP') }}"
     ansible_user: root
     ansible_ssh_private_key_file: "~/.ssh/id_ed25519"
   ```
2. Export `SERVER2_IP` and run `./deploy.sh deploy`
3. Ansible deploys to all hosts in parallel
